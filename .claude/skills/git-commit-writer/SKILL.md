## 반드시 따를 템플릿/컨벤션
- 제목은 `<type>: <한 줄 요약>` (`feat`/`fix`/`refactor`/`chore`/`docs` 등)
- 대부분 제목만으로 끝내지 않고, 빈 줄 하나 두고 **개조식 불릿 본문**으로 "무엇을 바꿨는지" 나열
- 사소한 변경(설정 하나 제거 등)만 제목 한 줄로 끝내기도 함 — examples.md 참고

## 작성 톤 (중요)
- 짧은 불릿 위주. 완전한 문장/서술형 문단 금지
- "~했습니다", "~를 진행하였습니다" 같은 서술형 어미 대신 명사형/개조식으로 ("~적용", "~분리", "~수정")
- 왜(why)가 중요한 항목만 한 줄 설명 추가, 나머지는 항목만
- 이 저장소의 변경 사항만 서술 — 다른 레포/서비스 이름 같은 외부 맥락을 끌어오지 않기

## 커밋 전 확인
- 커밋 제목·본문 초안을 사용자에게 먼저 보여주고 컨펌 받은 뒤 커밋할 것 (임의로 바로 커밋하지 않기)
